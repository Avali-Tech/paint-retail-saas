# Environment variables

The API validates its settings at start-up ([apps/api/src/config.ts](../apps/api/src/config.ts))
and refuses to start with a list of what is wrong (never the values). In AWS, Terraform sets them
on the ECS task definition ([modules/api](../infra/terraform/modules/api/main.tf)); secrets come
from Secrets Manager and are injected by ECS when the task starts.

## Web app (`apps/web`, build time)

Vite bakes these into the bundle when it is built (the deploy workflow builds per environment).
A DSN is public by design (it can only send events), so it is a repository variable, not a secret.

| Variable                  | Default                 | What it does                                                               |
| ------------------------- | ----------------------- | -------------------------------------------------------------------------- |
| `VITE_API_BASE_URL`       | `/api`                  | Where the browser calls the API                                            |
| `VITE_SENTRY_DSN`         | unset (off)             | Browser error tracking; repository variables `WEB_SENTRY_DSN_STAGING/PROD` |
| `VITE_SENTRY_ENVIRONMENT` | Vite mode               | Set to `staging` / `prod` by the deploy                                    |
| `VITE_SENTRY_RELEASE`     | unset                   | The commit SHA, set by the deploy                                          |
| `API_URL`                 | `http://localhost:3000` | Dev/preview proxy target only (not in the bundle)                          |

## Ops tasks (`packages/ops`)

| Variable                                 | Used by       | What it does                                                                |
| ---------------------------------------- | ------------- | --------------------------------------------------------------------------- |
| `DATABASE_URL`                           | both          | Injected from the same secret as the API                                    |
| `MIGRATIONS_FOLDER`                      | migrate       | Default `migrations` (copied into the image from `packages/db/migrations`)  |
| `DRILL_SOURCE_URL`                       | restore drill | Database to back up (default `DATABASE_URL`)                                |
| `DRILL_SOURCE_HOST`                      | restore drill | Replaces the host of the source URL, e.g. a point-in-time-restored instance |
| `DRILL_TARGET_URL` / `DRILL_TARGET_HOST` | restore drill | Server to restore onto (default: the source's server)                       |
| `DRILL_TOOLS`                            | restore drill | `local` (pg_dump 17 on PATH, the image default) or `docker`                 |
| `DRILL_KEEP`                             | restore drill | `true` keeps the restored database for inspection                           |

## GitHub (deploy workflow)

Repository variables (Settings → Secrets and variables → Actions → Variables). No secrets are
needed: AWS access is by OpenID Connect.

| Variable                                         | Value                                                                              |
| ------------------------------------------------ | ---------------------------------------------------------------------------------- |
| `DEPLOY_CONFIG_STAGING` / `DEPLOY_CONFIG_PROD`   | JSON of `terraform output -json github_environment_variables` for that environment |
| `PROD_APPROVERS`                                 | Comma-separated GitHub usernames who may approve production deploys                |
| `WEB_SENTRY_DSN_STAGING` / `WEB_SENTRY_DSN_PROD` | Optional browser Sentry DSNs                                                       |
